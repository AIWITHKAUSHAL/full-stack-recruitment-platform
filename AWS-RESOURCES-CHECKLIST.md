# AWS Resource Inventory and Destroy Checklist

This document records the AWS resources used by the **Mini Job Board Application
Tracker** and provides a checklist for confirming that the project has been
completely removed after teardown.

## Deployment identity

| Item | Current value |
|---|---|
| AWS account | `<AWS_ACCOUNT_ID>` (read locally with `aws sts get-caller-identity`) |
| AWS region | `us-east-1` (US East, N. Virginia) |
| Resource-name prefix | `mini-job-board-dev` |
| Project tag | `Project = MiniJobBoardApplicationTracker` |
| Environment tag | `Environment = dev` |
| Managed-by tag | `ManagedBy = Terraform` |
| CloudFront distribution | `<CLOUDFRONT_DISTRIBUTION_ID>` (read with `terraform output`) |
| Application URL | `<CLOUDFRONT_URL>` (read with `terraform output`) |

Most resources are regional. Select **US East (N. Virginia) / `us-east-1`** in
the AWS Console before checking them. CloudFront and IAM are global services.

Terraform currently tracks **63 AWS resource entries**. This includes supporting
configuration resources such as policies, security-group rules and route-table
associations; it does not mean there are 63 separate billable services.

## AWS services currently used

### 1. Amazon VPC

Purpose: provides the isolated network for the load balancer, ECS tasks and
database.

- VPC: `mini-job-board-dev-vpc` (`10.20.0.0/16`)
- Internet gateway: `mini-job-board-dev-igw`
- Two public subnets (`10.20.1.0/24` and `10.20.2.0/24`)
- Two private subnets (`10.20.11.0/24` and `10.20.12.0/24`)
- Public route table: `mini-job-board-dev-public-rt`
- Private route table: `mini-job-board-dev-private-rt`
- Four route-table associations
- ALB security group: `mini-job-board-dev-alb-sg`
- ECS security group: `mini-job-board-dev-ecs-sg`
- RDS security group: `mini-job-board-dev-rds-sg`
- Three ingress rules and three egress rules

The project does not create a NAT Gateway or an Elastic IP.

### 2. Elastic Load Balancing

Purpose: exposes the FastAPI service and routes requests to healthy ECS tasks.

- Application Load Balancer: `mini-job-board-dev-alb`
- Current DNS name: generated by AWS; read locally with
  `terraform -chdir=terraform output -raw alb_dns_name`
- Target group: `mini-job-board-dev-tg`
- HTTP listener: port `80`

### 3. Amazon ECS with AWS Fargate

Purpose: runs the containerized FastAPI backend without EC2 instances.

- Cluster: `mini-job-board-dev-cluster`
- Capacity provider: `FARGATE`
- Service: `mini-job-board-dev-backend`
- Task-definition family: `mini-job-board-dev-backend`
- Desired task count: `1`
- Task size: `0.25 vCPU` and `512 MiB` memory
- ECS service auto-scaling target: minimum `1`, maximum `4`
- CPU target-tracking scaling policy: target `60%`

Deployments and migration/seed commands may create additional task-definition
revisions or one-off ECS tasks. These are not all represented individually in
Terraform state, so the project destroy script handles them separately.

### 4. Amazon ECR

Purpose: stores the backend Docker images pulled by ECS.

- Repository: `mini-job-board-dev-backend`
- Repository URL: `<AWS_ACCOUNT_ID>.dkr.ecr.us-east-1.amazonaws.com/mini-job-board-dev-backend`
- Image scanning on push is enabled
- Lifecycle policy retains only the 10 newest images
- `force_delete` is enabled for teardown

### 5. Amazon RDS for PostgreSQL

Purpose: stores jobs, applications, users and application-status data.

- DB instance: `mini-job-board-dev-postgres`
- Engine: PostgreSQL 16
- Instance class: `db.t4g.micro`
- Storage: `20 GiB` gp3, encrypted
- Single-AZ deployment
- DB subnet group: `mini-job-board-dev-db-subnets`
- DB parameter group: `mini-job-board-dev-pg16`
- Public access is disabled
- Deletion protection is disabled
- Final snapshot is disabled
- Automated backups are deleted during teardown

Destroying this database permanently removes all project database data.

### 6. Amazon S3

Purpose: stores the React frontend and candidate resume uploads.

- Frontend bucket: `mini-job-board-dev-frontend-<AWS_ACCOUNT_ID>`
- Resume bucket: `mini-job-board-dev-resumes-<AWS_ACCOUNT_ID>`
- Public Access Block is enabled on both buckets
- AES-256 server-side encryption is enabled on both buckets
- The resume bucket has a lifecycle rule for uploaded resumes
- `force_destroy` is enabled on both buckets

S3 objects are created by deployments and users, not by Terraform individually.
The project destroy script empties the buckets before deleting them.

### 7. Amazon CloudFront

Purpose: serves the React frontend over HTTPS and proxies API requests to the
load balancer.

- Distribution ID: generated by AWS; read with `terraform output`
- Distribution domain: generated by AWS; read with `terraform output`
- Origin Access Control: `mini-job-board-dev-frontend-oac`
- CloudFront Function: `mini-job-board-dev-spa-rewrite`
- Origins: private S3 frontend bucket and the Application Load Balancer
- Price class: `PriceClass_100`

CloudFront deletion can remain in progress for several minutes because the
distribution must first be disabled.

### 8. AWS Systems Manager Parameter Store

Purpose: securely supplies the database URL and JWT signing key to ECS.

- SecureString: `/mini-job-board-dev/database_url`
- SecureString: `/mini-job-board-dev/jwt_secret_key`

The secret values must never be copied into this document or committed to Git.

### 9. AWS IAM

Purpose: gives ECS and GitHub Actions only the AWS permissions they need.

- Role: `mini-job-board-dev-ecs-execution-role`
- Inline policy: `mini-job-board-dev-ecs-execution-secrets`
- Managed policy attachment: `AmazonECSTaskExecutionRolePolicy`
- Role: `mini-job-board-dev-ecs-task-role`
- Inline policy: `mini-job-board-dev-ecs-task-s3`
- Role: `mini-job-board-dev-github-actions-role`
- Inline policy: `mini-job-board-dev-github-actions-policy`

The account-wide GitHub OIDC provider
`token.actions.githubusercontent.com` is currently **referenced as shared
infrastructure** because `create_github_oidc_provider = false`. It is not owned
by this Terraform state and must **not** be manually deleted when destroying
this project unless it is known that no other project uses it.

### 10. Amazon CloudWatch

Purpose: stores logs and provides operational metrics, a dashboard and an alarm.

- ECS log group: `/ecs/mini-job-board-dev`
- RDS log group:
  `/aws/rds/instance/mini-job-board-dev-postgres/postgresql`
- Dashboard: `mini-job-board-dev-dashboard`
- Alarm: `mini-job-board-dev-no-healthy-targets`
- Log retention: 7 days

Standard service metrics shown in CloudWatch are not separate Terraform
resources and stop being generated when their source resources are removed.

### 11. AWS Certificate Manager (optional, not currently created)

The Terraform configuration supports an ACM certificate for an optional custom
domain, but `custom_domain` is currently empty and `attach_custom_domain` is
false. Therefore, this project currently has no ACM certificate in its state.

The project does not create a Route 53 hosted zone or DNS records. If a custom
domain is enabled later, its DNS records remain at the external registrar and
must be removed there separately when they are no longer wanted.

## Recommended destruction procedure

Run these commands from the repository root:

```bash
# Save generated IDs and names locally before destroying. This file is ignored
# by Git and must not be committed.
terraform -chdir=terraform output > AWS-RESOURCES-CHECKLIST.local.md

# Recommended teardown. This is safer and more complete than calling
# `terraform destroy` directly.
make destroy

# Read-only AWS-side leftover check. Safe to repeat.
make destroy-check

# Terraform should print no resource addresses.
terraform -chdir=terraform state list
```

`make destroy` performs additional cleanup that plain `terraform destroy` does
not fully cover:

1. Stops standalone ECS migration or seed tasks.
2. Empties both S3 buckets, including object versions and delete markers.
3. Runs `terraform destroy` and retries once after an AWS consistency delay.
4. Deregisters, then permanently deletes, every ECS task-definition revision
   of the project family, including those created by deployments.
5. Runs the read-only AWS leftover checker, which also checks the project's
   IAM roles and policies by name.

## Manual post-destroy AWS Console checklist

Wait a few minutes if a service still shows an item in `Deleting` state, then
confirm every applicable checkbox below.

### Global services

- [ ] **CloudFront > Distributions:** the ID saved in `AWS-RESOURCES-CHECKLIST.local.md` is absent.
- [ ] **CloudFront > Functions:** `mini-job-board-dev-spa-rewrite` is absent.
- [ ] **CloudFront > Origin access:** `mini-job-board-dev-frontend-oac` is absent.
- [ ] **IAM > Roles:** all three `mini-job-board-dev-*` roles listed above are absent.
- [ ] **IAM > Identity providers:** do not delete the shared GitHub OIDC provider.

### Regional services (`us-east-1`)

- [ ] **ECS > Clusters:** `mini-job-board-dev-cluster` is absent.
- [ ] **ECS > Task definitions:** no ACTIVE or INACTIVE revision of `mini-job-board-dev-backend` remains.
- [ ] **ECS > Tasks:** no project service task or standalone task remains.
- [ ] **ECR > Private repositories:** `mini-job-board-dev-backend` is absent.
- [ ] **RDS > Databases:** `mini-job-board-dev-postgres` is absent.
- [ ] **RDS > Snapshots:** no snapshot beginning with `mini-job-board-dev` remains.
- [ ] **RDS > Automated backups:** no retained project backup remains.
- [ ] **RDS > Subnet groups:** `mini-job-board-dev-db-subnets` is absent.
- [ ] **RDS > Parameter groups:** `mini-job-board-dev-pg16` is absent.

- [ ] **ACM:** no project certificate exists (only applicable if a custom domain was enabled later).

### Account-wide tag search

As a final check, open **AWS Resource Groups & Tag Editor**, search all supported
resource types in `us-east-1`, and filter by:

```text
Project = MiniJobBoardApplicationTracker
```

The search should return no resources. Some automatically created or global
resources do not support the same tag search, which is why the service-specific
checks above are still required.

## Services deliberately not used

This project does not create EC2 instances, NAT Gateways, Elastic IPs, Route 53
hosted zones, Lambda functions, API Gateway APIs, DynamoDB tables, Secrets
Manager secrets, SNS topics, SQS queues, WAF web ACLs or Kubernetes/EKS resources.
